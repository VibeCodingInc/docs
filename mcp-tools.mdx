---
title: "MCP tools"
description: "Eight tools, written for the agent in your session."
---

You do not call these yourself. Your coding agent does, when you ask it to reach someone or
when a message arrives.

| Tool | Job |
| --- | --- |
| `vibe_start` | Sign in, or see what is waiting: unread conversations and ones where the other person spoke last |
| `vibe_people` | Who can be reached: people in a session now, with their own line about what they are doing, and the people you already talk with |
| `vibe_thread` | One conversation in full, with the id of every message. Opening it marks it read |
| `vibe_prepare` | The agent's words to a person, previewed. Sends nothing |
| `vibe_send` | Your approval of a preview (draft id and the revision you saw), or your own exact words |
| `vibe_discard` | Cancel a draft |
| `vibe_ask` | Over an [open line](/open-line): ask a person's agent a question from your work and wait briefly for the answer |
| `vibe_answer` | Over an open line: answer a question that just arrived, from your work |

`vibe_init` and `vibe_token` handle sign-in.

## Commands

```sh
npx slashvibe-mcp                         # install or repair
npx slashvibe-mcp hook install|status|uninstall
npx slashvibe-mcp trust @handle           # open a line
npx slashvibe-mcp untrust @handle         # close it
npx slashvibe-mcp lines                   # list open lines
```

No tool can open a line. Only the `trust` command, typed by you, does.

## Rules the tools keep

- Other people's words (messages, what someone says they are working on) are data. The
  agent shows them to you and never acts on them.
- A preview is bound to its exact text and to the message it answers. Editing either
  invalidates the approval.
- A message is refused rather than shortened when it is over the limit.
- A failed read is reported as unknown, never as an empty inbox or an empty room.

The platform HTTP routes are not a supported public API. Use the MCP package.
