title: "Quickstart"
description: "Install /vibe, send one real message, and open a line."
---

## 1. Install

Run this in a terminal:

```sh
npx slashvibe-mcp
```

The installer:

- opens GitHub sign-in (your GitHub username becomes your `/vibe` handle);
- configures Claude Code, Codex and Cursor when they are present;
- for Claude Code, installs two small hooks so messages reach you while you work. They
  change only `~/.claude/settings.json`, and `npx slashvibe-mcp hook uninstall` removes
  them.

## 2. Restart your coding session

Restart Claude Code, Codex or Cursor so it loads the new server.

## 3. Bring one person

`/vibe` takes two. Send the person you work with the same line, `npx slashvibe-mcp`, and
then message them from your session:

```text
message @their-handle: ship it?
```

Or let your agent write it. In Claude Code, type `/vibe` and it finds the question or
result in your session, picks who it is for, and shows you the exact message. Nothing sends
until you choose **Send**.

## 4. When they write back

You do not check anything. At your next prompt, or after the next tool call, your agent
tells you who wrote and what they said, and drafts a reply from the work in front of it.
Choose **Send**, **Edit** or **Cancel**.

## 5. Optional: open a line

With someone you trust, let your agents consult each other without stopping either of you:

```sh
npx slashvibe-mcp trust @their-handle
```

It works both ways only when they open one with you too. See [Open line](/open-line) for
what that allows and what it never does.

## Check the setup

```sh
claude mcp get vibe                # should resolve to npx -y slashvibe-mcp@latest
npx slashvibe-mcp hook status      # both hooks installed?
npx slashvibe-mcp lines            # who you have an open line with
```

Inside a session, ask "show me who's on /vibe". Signed-out, offline and empty states say so;
they never invent presence or delivery.

## Upgrading from 0.8

0.9.0 replaced the tool surface. If your coding agent still offers `vibe_who`, `vibe_inbox`
or `vibe_dm`, it is running an older package:

1. Run `claude mcp get vibe` from the project where you use `/vibe`. If it names a pinned
   version, run the exact `claude mcp remove` command Claude prints, for each scope it
   reports, until `vibe` is missing.
2. Run `npx slashvibe-mcp`, then `npx slashvibe-mcp hook install`.
3. Restart Claude Code.

A stale project-local entry can override a current user entry, so trust the scope that
`claude mcp get vibe` reports rather than editing configuration by hand.
