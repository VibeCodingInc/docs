## 1. Install

Run this in a terminal:

```sh
npx slashvibe-mcp
```

The installer opens GitHub sign-in and configures supported coding hosts when present.
Your GitHub username becomes your initial `/vibe` handle.

Claude Code and Codex are the verified terminal paths. Setup also writes Cursor's config;
that does not yet establish a verified end-to-end Cursor journey.

## 2. Restart your coding host

Restart Claude Code or Codex so it loads the new MCP server and installed command.

## 3. Open a conversation from your work

Resume a session where you have already been working. Open the installed `/vibe` command
from your host's command picker. No bio form, and no need to restate the project.

Your agent uses the session to propose a useful conversation. Choose a draft, then review
the exact recipient, message, and chosen links. Choose **Send to @handle**, **Edit**, or
**Cancel**. Opening the draft sends nothing; edits get a fresh preview.

If no suggestion fits, skip it. You can still ask directly:

```text
message @handle — <your question>
```

Replace `@handle` with someone you already know. The signed-in people list also shows
people who explicitly chose to be findable. A presence dot does not promise a reply.

<Note>
  Setup preserves any existing `/vibe` command. If that name was taken, the new command
  is installed beside it as `/vibe-moves`. Use the name setup reports. The command and
  its picker are host features, not a shell executable named `/vibe`.
</Note>

## Claude Code: show waiting messages at session start

```sh
npx slashvibe-mcp hook install
```

Restart Claude Code after installing the hook. Waiting messages can then appear at the top
of a later session.

<Note>
  The pilot hook is read-only. It does not mark a message delivered or read, so the same
  waiting message may appear again.
</Note>

## Check the setup

For Claude Code, inspect the configured server:

```sh
claude mcp get vibe
```

The command should resolve to `npx -y slashvibe-mcp@latest`.

If you installed the optional hook, check it separately:

```sh
npx slashvibe-mcp hook status
```

Inside the coding host, ask “show me who's on /vibe” or “did anyone message me?” Signed-out, offline,
and empty states should say so; they should not invent presence or delivery.

## Returning from an older Claude Code install

Older installs can leave `vibe` pinned to an earlier package. The installer currently keeps
an existing MCP entry instead of replacing it, so check from the project directory where
you plan to use `/vibe`:

```sh
claude mcp get vibe
```

If it names a pinned version, run the exact scope-specific `claude mcp remove` command that
Claude prints. Check again because `vibe` can exist in more than one scope. Remove only the
named `vibe` entry until `claude mcp get vibe` reports that it is missing, then run:

```sh
npx slashvibe-mcp
claude mcp get vibe
```

Confirm that the new entry uses `slashvibe-mcp@latest`, then restart Claude Code. A stale
project-local entry can override a current user entry, so trust the scope reported by
`claude mcp get vibe` rather than editing configuration JSON by hand.

## Need the Mac companion?

Vibe Buddy is optional. Install it after terminal messaging works if you want a quiet,
persistent view of people, messages, and local coding sessions. See [Vibe Buddy](/buddy).
